8 Distributed Computing Patterns
01
🏗️
Multi-Node Service-Oriented Architecture
6 independent services communicate via well-defined APIs: Mobile Edge, FastAPI Orchestrator, Groq STT, OpenAI LLM, Cartesia TTS, and Supabase/Redis. Each is independently deployable and upgradeable.
SOA
02
🔌
WebSocket Bidirectional Message Passing
Persistent WS connection on /ws/{session_id} carries typed messages: audio_chunk, turn_end, tts_chunk, correction_card. Replaces polling with push-based real-time communication.
Real-Time
03
⚡
Redis Distributed State Management
Upstash Redis stores per-session state (key: session:{id}, TTL 2h). Holds conversation history (capped 60 turns), pronunciation scores, and CEFR level — enabling stateless backend scaling.
Upstash Redis
04
⚙️
Async Background Task Execution
Three fire-and-forget coroutines run per turn: Stream B (LLM→TTS pipeline), Stream C (grammar check, 500ms timeout), and silence nudge. asyncio.gather() runs B and C in parallel without blocking audio delivery.
asyncio
05
📡
Edge-Cloud Hybrid Computing
Voice Activity Detection runs on-device (React Native amplitude metering, 32ms resolution) to eliminate cloud round-trip latency for speech boundaries. Only captured audio is sent to cloud AI services.
On-Device VAD
06
🔄
Fault-Tolerant Fallback Routing
Every AI provider has an automatic fallback: GPT-4o → Groq Llama-3.3-70b (conversation), GPT-4o-mini → Groq Llama-3.1-8b (corrections), Cartesia → Edge-TTS (audio), Whisper → Azure Speech (pronunciation scoring).
Multi-Provider
07
🌊
SSE Streaming Pipelines
LLM tokens stream via OpenAI/Groq async generators; Cartesia TTS uses Server-Sent Events (/tts/sse) delivering base64 audio chunks. Sentence-boundary buffering gates TTS calls to avoid choppy synthesis.
SSE · Streaming
08
📐
Horizontally Scalable Stateless Backend
FastAPI runs on Railway (Procfile: uvicorn main:app --port $PORT). No in-process state — all session data is in Redis, all persistence in Supabase. Any number of replicas can serve the same session.
Stateless · Railway
